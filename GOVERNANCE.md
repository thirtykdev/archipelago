# Governance

Archipelago was founded by ThirtyK, which maintains it today and names the
maintainers. This document describes how that works now and how it is
intended to change.

## Today

- One maintainer (the founder) merges changes and cuts releases.
- Decisions that shape the project are recorded as architecture decision
  records under `docs/adr/`, each with context, decision and consequences.
- Contributions are reviewed in pull requests. The core and the importers
  get the strictest review.

## Adding maintainers

A contributor who has landed several reviewed changes and shown judgment on
the clean-room and read-only rules may be invited to maintain. Maintainers
can merge, triage and review. Releases stay with the founder until the
release process is automated and verified.

## Later

When there are three or more active maintainers, a maintainer council
decides by lazy consensus on the ADRs, the roadmap and the release policy.
ThirtyK keeps the trademark; the code carries the open licenses in
LICENSING.md. The project is independent of every manufacturer and accepts
no vendor endorsement.
